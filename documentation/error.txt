true
→ This is not a PowerShell built-in command
→ PowerShell treats true as a boolean literal ($true), not the Unix-style no-op command
→ Because it's not followed by any operator or cmdlet, PowerShell tries to execute true as if it were a command/program → fails with the familiar error:

true: The term 'true' is not recognized as a name of a cmdlet, function, script file, or executable program.

Why do people write ; true at the end?This is a very common pattern in bash/zsh/sh scripts (Linux/macOS) where:bash

git add ... ; git commit ... ; true

Ensures the overall command chain exits with status 0 (success), even if the commit fails (e.g. no changes to commit)
Very useful in Makefiles, CI scripts, or pre-commit hooks where you don't want a failed commit to block the next step

On Windows PowerShell, the equivalent ways to achieve the same "always succeed" behavior are:powershell

# Option 1: Just ignore errors (most common & clean)
git add .github/workflows/python-tests.yml ; git commit -m "ci: ..." 2>$null

# Option 2: Use ; $LASTEXITCODE = 0  (forces success exit code)
git add ... ; git commit ... ; $LASTEXITCODE = 0

# Option 3: Use try/catch (more verbose but very explicit)
try {
    git add .github/workflows/python-tests.yml
    git commit -m "ci: set workflow permissions and expose GITHUB_TOKEN as GH_TOKEN"
} catch {}

But in most cases — especially if this is just a local commit before pushing — you can safely remove the ; true entirely:powershell

git add .github/workflows/python-tests.yml
git commit -m "ci: set workflow permissions and expose GITHUB_TOKEN as GH_TOKEN"
